# Evolution loop v2 preregistration (committed before any v2 run, pilots included)

Status: second offline run of the evolution engine (ADR 0012) on the FISHERY. Scripted agents only; no model API call, no network. Nothing here is a research result about LLM agents. Written after docs/results/evolve.md was read; it fixes the v1 weaknesses named there (finite seam key set, blind front-prevalence test, saturated objectives, no redundancy check, overfit to a fixed training test). This file is not edited after the first run; results go in docs/results/evolve-v2.md. Pilots, if any, are labeled EXPLORATORY, are not results, and change no parameter below.

## What stays from v1 (docs/results/evolve-prereg.md)

Fishery world, N = 4 agents, 12 sub-rounds, capacity 100, gate and oracle thresholds, the eight training mixes T1 to T8 (9 runs), the five mutation operators and weights, proof filter at k = 3 (open is rejected), NSGA-II style selection with constraint dominance on the yield floor (yield = mean catch of the all-compliant mix / 5, floor 0.8), bloat tie-break, hard cap 12 cards, seed rule sets `v2`, `minimal`, `tight`, population mu = 10, lambda = 10, 12 generations after generation 0, `random.Random(seed)` only.

## What changes

1. **Seam measure: per-candidate exploit prevalence against a fresh adversary sample.** A fixed ADVERSARY POOL of 96 scripted mixes is defined in code (`world_api.ADVERSARY_POOL`): exploit size in {5, 7, 10}, number of exploiters in {1, 2, 3, 4} (the rest Compliant), pattern in {every sub-round, even sub-rounds, last two sub-rounds, first three sub-rounds}, start month in {0, 2}. Each generation g, seeded by (evolution seed, g), draws a fresh SELECTION sample of 6 adversaries and a disjoint AUDIT sample of 6 from the pool. **Exploit prevalence of a candidate = share of the selection sample whose gated run the oracle fails** (every executed action passed the gate, run judged bad). The count cannot fall by exhaustion: the sample is redrawn. Every population member is re-scored under each generation's sample (and conditions) before selection, so scores in one generation are comparable. The audit sample is never used in selection; it measures the generation's elite (highest mean objective on the feasible front) only.
2. **Four objectives (all maximized):** sustainability (mean month-end pool / 100), fairness (1 - Gini of per-agent catch), seam_free = 1 - exploit prevalence, and a NEW continuous **efficiency** = min(1, mean monthly total catch / 40). Sustainability, fairness and efficiency are means over all mixes of the evaluation (T1 to T8 plus the 6 selection adversaries); seam_free is over the adversaries only. Efficiency pulls against sustainability and seam_free (a rule that lets fishers take more is more efficient and more exploitable), so the front is meant to stay non-trivial. Hypervolume is computed in 4-D (reference point 0).
3. **Redundancy check (new, fourth reason for proof-filter rejection).** A card (must or must_not) is redundant if the conjunction of the other cards implies it over the bounded domain (Z3: pool 0..100, month_total 0..100, pool + month_total <= 100, catch -100..100; negative catch is in the domain so "no negative catch" is not vacuous). Mutants with a redundant card are rejected (reason `e_redundancy`, counted inside proof_rejected). For `patch` (add-a-card) mutants the redundant card is removed instead (the pruned set is then evaluated, unless it duplicates a known set). Logical implication only: sanctions and glosses are ignored (the fishery harness does not enforce sanctions; ASSUMED).
4. **Two training arms, same evolution seeds:** FIXED = every generation evaluated at regrowth x2.0 (remaining stock doubles, cap 100), 6 months, start pool 100 (the v1 training condition). VARIED = each generation, seeded, draws conditions from the TRAINING DISTRIBUTION: regrowth in {1.5, 2.0, 2.5, 3.0} x months in {5, 6, 7} x start pool in {100, 80}. Adversary sampling is identical in both arms, so the arms differ only in conditions.
5. **Runs:** 3 seed rule sets x 3 evolution seeds (0, 1, 2) x 2 arms = 18 runs. Run in parallel processes (each run is deterministic under its seed).

## Exam 2 (new, untouched; defined now; used once per run after the last generation, never in selection or design)

Conditions: regrowth x1.7, **9 months**, **start pool 60**, 12 sub-rounds. None of the training-distribution values: not a training regrowth, month count or start pool. Mixes (all unseen; their agent classes are not in the adversary pool or T1 to T8): X1 all_compliant (yield check only), X2 steady_four (4 agents catching 4 every sub-round), X3 front_load (4 agents catching 8 in sub-rounds 0 to 2 of every month), X4 ramp (2 Ramp agents catching min(10, 1 + 2 x month) every sub-round, 2 Compliant), X5 late_sleeper (2 Sleepers starting month 4, size 7, plus 2 Compliant), X6 mixed_two (FrontLoad, Steady(2), Compliant, Compliant). Exam prevalence = share of X2 to X6 failing the oracle; exam seam_free = 1 - that; sustainability, fairness, efficiency = means over X1 to X6. Exam 1 (v1: regrowth x1.5, 8 months, tiny_hoarder, last_minute, mixed_unseen) is already seen; it is reported as a secondary check only. The seed spec is exam-scored as a baseline.

**Reference score (the "training score" in the gap):** one common evaluation for every run and arm, so the arms are compared on the same footing: x2.0, 6 months, start 100, T1 to T8 plus 12 reference adversaries drawn from the pool with the fixed seed 7777 (not a selection or audit sample of any run; ASSUMED: the pool is shared, the draw is not). GAP = reference score minus exam-2 score, per objective.

## Predictions (numeric thresholds; failures stay failed)

1. **Prevalence falls on the elite.** Per run: mean audit prevalence of the generation elite over generations 10 to 12 <= mean over generations 0 to 2 minus 0.15. True in >= 10 of 18 runs and in >= 4 of 9 in each arm. (Audit prevalence has granularity 1/6; the sample is fresh each generation.)
2. **Varied training shrinks the exam-2 gap.** Per (seed rule set, seed) pair, gapavg = mean of the sustainability gap and the seam_free gap. Mean of (FIXED gapavg - VARIED gapavg) over the 9 pairs >= 0.05, and VARIED smaller in >= 6 of 9 pairs. Secondary (also scored): VARIED mean exam-2 seam_free >= FIXED mean exam-2 seam_free + 0.05, so the gap did not shrink only because the reference score fell.
3. **Redundancy.** Of mutants that pass the four proofs (non-duplicate, within the cap), the share flagged redundant (rejected or repaired), pooled over the 18 runs, is between 5% and 40%; at least one mutant is flagged in >= 14 of 18 runs; and 0 of the 18 final elites contain a card implied by the others. The v1 case (F3 plus F4 flipped to `must catch >= 0`) must be flagged by the check (unit test).
4. **No early saturation.** Saturated at generation g = the front has >= 8 members and all have identical objective vectors (rounded to 2 decimals). N = 6: saturation first happens after generation 6, or never, in >= 15 of 18 runs. Non-trivial front: at generation 12, >= 3 distinct (2 decimal) objective vectors on the feasible front in >= 12 of 18 runs. No final elite has all four objectives >= 0.95.
5. **Path dependence (reported either way).** Per arm: the mean reference objective vector (4-D) of the final elites per seed rule set; path dependence is present if the largest pairwise Euclidean distance among the three seed sets is > 0.10. Prediction: present in both arms. If <= 0.10 it is reported as convergence. Also reported: card-signature (deontic, aim, conditions) Jaccard overlap of the elites.

Exploratory, no prediction: elite vs seed on exam 2 (by arm, by seed rule set); exam 1 gaps; which operators were rejected.

## Runtime

Measured before writing this: one 9-run evaluation about 0.18 s, one proof check 0.01 s. Estimate: about 20 re-evaluations of 15 runs per generation x 13 generations, about 80 s per evolution run, 18 runs on 8 cores in a process pool, about 4 minutes. The script must finish in about 15 minutes. If a pilot shows it will not, the setup is shrunk by a committed amendment to this file (population or generations) BEFORE the real run.
