# Empowerment: preregistration (2026-11-10)

Status: written and committed BEFORE any empowerment number is computed. Never edited after. Results go in `docs/results/empowerment.md`. Nothing here is a result. Design source: ADR 0011 decision 2 (freedom as empowerment, reported alongside the hand-made score first; Klyubin, Salge and Polani for empowerment, Turner et al. for power-seeking, both from memory, verify).

## Definition

Empowerment of agent i in state s at horizon k = the number of DISTINCT future states i can still reach within k steps, given (a) the rules (the gate decides which of i's proposed actions take effect) and (b) the other agents' policies (fixed, deterministic scripts). i chooses freely among its action menu at every step. bits = log2(reachable). A step is one round: every agent acts once, in index order; i's action is the free choice, the others' actions come from `policy_of_others`.

- "State" for counting is a key that drops the clock: fishery key = (pool, month_total, i's cumulative catch); VPGG key = i's cumulative payoff rounded to 9 places. ASSUMED: i's own holdings count as part of its future (what it has, not only what the world is). Reachable = the union of keys over steps 0..k, start state included (so reachable >= 1, bits >= 0). ASSUMED: the union over steps, not the exact-k set, because the author wrote "within k steps".
- Exact bounded enumeration: layers of distinct full states, deduplicated. A cap of 20000 action expansions per call. If the cap is hit the result carries `bound_hit: true`, the count is a lower bound, and the verdict is reported as "open", never as a number to compare.
- Blocked actions: an action the gate rejects has no effect (fishery, as in run_fishery) or falls back to "join" (VPGG, as in vpgg.effective_actions). The same code path for the focal agent and for the others.
- Terminal state (months exhausted): absorbing. Months 0 to 4 starts are measured, so k=3 never hits the end.
- Interface: `empowerment(world, spec, state, agent, k, policy_of_others) -> {"reachable", "bits", "bound_hit"}` (plus `k`, `expanded`, `verdict`). A world supplies `actions(state, agent)`, `step(state, spec, agent, action, policy_of_others)`, `key(state, agent)`, `is_terminal(state)`. A household adapter implements those four.
- `collective_empowerment` = min and mean of bits over agents. `power_seeking_index(series, i)`: series[t][j] = bits of agent j at time t. gain_i = series[-1][i] - series[0][i]; others_change = mean over j != i of the same difference. ASSUMED reading: psi_i = gain_i - others_change (own change relative to others'). The literal "own gain minus others' loss" would score a universal rise as power-seeking (everyone +2 gives +4); the differential gives 0. Reported with its two parts, so any reading is recoverable. Flag power_seeking = gain_i > 0 and others_change < 0.

## Settings (fixed now)

- Horizon k = 3 rounds. No randomness: the worlds and policies are deterministic, so there are no seeds and no sampling error. Every number is exact at k=3 (or open).
- VPGG: N = 5, r = 3, c = 1, sigma = 1 (the vpgg prereg parameters). Focal agent plus 4 others; the others' strategies are one of C, D, L, all 15 multisets of the 4 others (all 15 compositions stand in for "every agent", since an agent's view is fixed by the others). Regimes: rules/vpgg/compulsory and voluntary. Under compulsory the others' L falls back to join-and-defect (the gate), so intended composition is held fixed across regimes. Focal menu: join, contribute, abstain.
- Fishery: 4 agents [Exploiter, Exploiter, Compliant, Compliant] (mocks.py), indices 0 to 3, in that action order; 6 months, 12 subrounds, capacity 100. Focal catch menu (0, 1, 3, 5, 10, 15) (15 breaks the per-action cap F1 in both specs). Seamed spec = rules/fishery F1 to F4; patched spec = seamed plus the scripted P1 from `propose_patch` on the exploiter run (per-month cap 40). The trajectory is the actual run of those scripts under each spec; empowerment is measured at the start of months 0 to 4 (subround 0 state) and, secondarily, at all 12 subround states of month 0.
- Hand-made freedom: VPGG = vpgg.run's formula, 0.5 E + 0.5 E R with E = gate permits abstain at invited=5, R = real_option (computed directly, no simulation). Fishery has none in the repo; ASSUMED proxy "option fraction" = fraction of the 6-action menu the gate permits at the state (physical clamp ignored; F2 is a gate card so it counts), mean over the measured states. It is the fishery analogue of household_oracle's `opts` term.

## Predictions (numeric, committed before any run)

1. **VPGG voluntary > compulsory.** For each of the 15 compositions, bits(voluntary) > bits(compulsory), strict. Derived by hand beforehand: composition LLLL ties (voluntary: every focal action pays sigma = 1, so sums 0,1,2,3 = 4 states; compulsory: others forced to join, focal pays 0 or -0.4 per round = 4 states; both 2.0 bits). So the stated prediction is 14 of 15 strict, LLLL a tie, no composition with compulsory > voluntary. Any other tie is a surprise (coincident payoffs) and is reported. PASS = no composition favors compulsory and at least 13 of 15 are strict. Mean difference over the 15 compositions >= 0.5 bits.
2. **Fishery, seamed vs patched, months 1 to 4 (start-of-month states).**
   - 2b (compliant agents 2, 3): patched bits > seamed bits in every month 1 to 4. Seamed is exactly 0 bits (the exploiters empty the pool in month 0, 0 doubles to 0, F2 blocks every catch above 0, so nothing is reachable but the status quo). Patched >= 3.0 bits (>= 8 reachable) for each compliant agent in each month 1 to 4.
   - 2a (exploiters 0, 1), the author's claim that the patched spec lowers exploiters' empowerment in later months: I EXPECT THIS TO FAIL as stated. Seamed is exactly 0 bits from month 1 on, which patched cannot go below, so "lower in later months" cannot hold by construction. Preregistered anyway: PASS only if patched < seamed for both exploiters in months 1 to 4 (predicted fail; predicted patched >= 3.0 bits).
   - 2a' (the version that can hold): in month 0, where both specs start from a full pool, mean empowerment of the exploiters over the 12 subround states is lower under patched than seamed (the cap binds at subround 1, the pool lasts until about subround 4). Predicted lower by >= 0.3 bits. Uncertain: crossing the month boundary inside k=3 lets patched agents see next month's restored pool near the end of the month; this may reverse it.
3. **Agreement of empowerment with the hand-made score.** Agreement means: same sign of the (regime A minus regime B) difference on both measures, and neither difference zero. A tie on either side is "uninformative", never agreement.
   - 3a VPGG: hand-made 1.0 (voluntary) vs 0.0 (compulsory); with prediction 1, agree. Predicted AGREE.
   - 3b Fishery patched vs seamed, months 1 to 4, per role: option fraction at month start is 5/6 (patched; 15 blocked) vs 1/6 (seamed; only catch 0 passes F2 at pool 0), so patched > seamed; with 2b, AGREE for compliant agents. For exploiters they also agree in sign (patched > seamed on both), which is the disagreement with claim 2a, not between the measures.
   - 3c Where empowerment sees what the hand-made score cannot: under the patched spec at month start, the option fraction is equal for all four agents (5/6) but empowerment depends on seat order against the shared cap: exploiter 0 (first to act) has strictly more bits than compliant agent 3 (last) in at least 3 of months 1 to 4. Predicted so.
4. **Power-seeking index is for grabs, not for shared collapse.** Over the month-start series months 0 to 4 in the seamed run, every agent's empowerment falls to 0 and no agent gains: predict gain_i <= 0 for all four, no agent flagged power_seeking, and |psi_i| <= 1.0 bit for all four. In the patched run: no agent flagged power_seeking either (predicted).
5. **Cap.** No call hits the cap of 20000 expansions at k=3 (the largest tree is 6^3 = 216 paths in the fishery). Any bound_hit is reported as open.

## What counts as the result

Each prediction is reported pass or fail with its numbers. The prereg is not edited. These are statements about deterministic scripted worlds at k=3, one menu, and one parameter point; they say nothing about LLM agents or the household. Empowerment here is also not "safe": reachable counts options, not whether any of them is good.
